# Реальная модель передачи аудио

Публичная страница: `course/reference/channel-coding-audio.qmd`. Она включена только
в справочник. Материалы лекций и карта курса не меняются.

## Определение шума

**Во всех режимах слайдер задаёт SNR = средняя мощность передаваемого сигнала /
мощность шума**, `SNR_dB=10*log10(Ps/Pn)`, `var(n)=Ps/10^(SNR/10)`.
При 0 dB мощности сигнала и шума равны. Определение не меняется при переключении.

Аналоговый канал: `y=x+n`, `Ps=mean(x²)`. Исходный сигнал нормирован по пику до
0.85, а SNR использует его среднюю мощность, а не пик.

Цифровой канал: `0→+1`, `1→−1`, поэтому `Ps=mean(symbols²)=1` и
`var(n)=1/10^(SNR/10)`. Для декодера Sionna подаются logits
`log(P(1)/P(0))=-2*y/var(n)`. У некодированной BPSK при 0 dB теоретическая BER
равна `0.5*erfc(sqrt(0.5))=0.1586553`. Это модель вещественных символов с AWGN
и идеальной синхронизацией; шум вводится до решения по битам, а не в PCM-аудио.

Сравнение не уравнивает время передачи, полосу и информационную скорость.
При одинаковом SNR и мощности символа LDPC тратит втрое больше символов и энергии на информационный
бит. Это намеренно показанная цена надёжности.

## Выбранный код

Проверена Sionna 2.2.0 (`sionna-no-rt`), современная версия на PyTorch.
Использованы `LDPC5GEncoder(k=2048,n=6144)` с готовым rate matching и
`LDPC5GDecoder(cn_update="boxplus-phi",num_iter=30)` с мягким BP, flooding schedule,
стандартным пределом LLR 20. Выбор base graph и lifting выполняет Sionna.
Это инструмент реализации LDPC, а не урок о стандарте 5G; CRC, ARQ и HARQ отсутствуют.

Скорость **R=1/3**: 2048 информационных битов в блоке, 6144 передаваемых символа.
Фрагмент содержит 262144 информационных бита, ровно 128 блоков без padding;
передаётся 786432 символа. Для заменяемого WAV manifest отдельно учитывает padding,
эффективные накладные расходы и число реально переданных битов.

Документация используемых API:
[encoder](https://nvlabs.github.io/sionna/phy/api/fec/ldpc/sionna.phy.fec.ldpc.LDPC5GEncoder.html),
[decoder и знак logits](https://nvlabs.github.io/sionna/phy/api/fec/ldpc/sionna.phy.fec.ldpc.LDPC5GDecoder.html),
[установка](https://nvlabs.github.io/sionna/installation.html).

## Измеренный выбор

Сравниваются три кандидата: `(k,n,BP)=(1024,3072,20)`, `(2048,6144,30)` и
`(2048,8192,40)`. Каждый использует 128 блоков случайных информационных битов на
точку. Измерения воспроизводимы: PCG64, payload seed 20261102, noise seed 20261202.
Один набор стандартного шума масштабируется на всей сетке SNR; это снижает случайные
различия между соседними точками, но не является независимыми испытаниями по SNR.

Выбранный кандидат (случайные данные):

| SNR, dB | BER после LDPC | FER | Ошибочные блоки |
|---:|---:|---:|---:|
| −3 | 0.243801 | 1 | 128/128 |
| −2 | 0.137150 | 0.992188 | 127/128 |
| −1.75 | 0.0618286 | 0.765625 | 98/128 |
| −1.5 | 0.00907516 | 0.187500 | 24/128 |
| −1.25 | 0.000278473 | 0.023438 | 3/128 |
| −1 | 0 | 0 | 0/128 |
| 0 | 0 | 0 | 0/128 |

Для короткого блока при −1 dB FER ещё 7.81 %, поэтому выбран более длинный блок.
Скорость 1/4 даёт запас, но лишняя избыточность не нужна: 1/3 уже достигает цели
около 0 dB и показывает отчётливый waterfall около −1.5 dB.

Полная кривая и исходные счётчики: [benchmark.csv](benchmark.csv).
График всех кандидатов: [benchmark.svg](benchmark.svg). На логарифмических осях
нулевые ошибки условно отображаются ниже `1/N`; это не измеренный ненулевой BER.

При 0 dB в каждом из 128 блоков выбранного кода не обнаружено ошибок. Это конечная
выборка, а не доказательство нулевой вероятности ошибки: при независимых блоках
односторонняя 95%-граница FER для 0/128 составляет около 2.31 %. Простая BER-граница
по правилу `3/N` требует независимости битовых ошибок, которую BP не гарантирует.

На **реальном синусоидальном фрагменте** при 0 dB uncoded BER = 0.158615112;
LDPC channel BER = 0.158176422, post-BER = 0, FER = 0/128. При −2 dB LDPC
post-BER = 0.125808716, FER = 126/128; при −3 dB post-BER = 0.242023468, FER = 128/128.
В некодированном режиме при 0 dB повреждены 24495 из 32768 PCM-отсчётов;
при 11 dB — 56, при 12 dB — 3, при 16 dB — 0. Такая разница в плотности ошибок
объясняет переход от плотного шума к редким щелчкам.
Все значения аудиокривой и точные счётчики сохранены в публичном manifest.

## Источник и сохранение результата

Локально синтезируется 4.096 s моно при 8 kHz. Восемь последовательных созвучий
имеют основные частоты 261.6256, 329.6276, 391.9954, 523.2511, 440, 391.9954,
329.6276, 293.6648 Hz; каждое — сумма синусов с отношениями частот 1, 1.25, 1.5
и амплитудами 1, 0.45, 0.3. Окно sin² обнуляет границы для плавного повторения.
Звук создан программно для этого проекта, внешних записей нет.

Перед цифровой передачей: равномерный unsigned PCM8 с уровнями −1…+1;
MSB first; квантование `round((clip(x,-1,1)+1)*127.5)`.
Блоки с ошибками проигрываются как декодированы, без concealment, фильтрации или
отбрасывания кадров. Остаточный шум квантования слышен и при нулевом BER.

Все результаты сохраняются с **одинаковым** коэффициентом усиления, выбранным по
максимальному пику всей сетки, чтобы аналоговый шум при −6 dB не клиппировался.
Отдельной нормализации результатов нет. Общий объём аудиопакетов — 4.6 MB.
Для каждого цифрового результата manifest также содержит число повреждённых PCM-отсчётов.
Редкие ошибки старших битов вызывают отдельные выбросы; при высокой плотности они
сливаются в шум. Это не искусственный AWGN после восстановления PCM. Для наблюдения
редких ошибок подходит Digital при 12 dB. Аналоговый исходный сигнал остаётся слагаемым
в сумме x+n даже при отрицательном SNR; тоны могут быть различимы под широкополосным шумом.

Waveform показывает огибающую min/max всего фрагмента; масштаб общий для обеих волн
и обновляется для текущего результата. Cursor соответствует аудиочасам.

Браузер предварительно загружает пакеты, создаёт AudioContext только после Play,
проигрывает циклически, переключает заранее рассчитанные данные без обращения к серверу,
сохраняет фазу и делает линейный crossfade 35 ms. Pause использует спад 25 ms.
Слайдер дискретный, шаг 1 dB. Модель и UI разделены; внешних JS-библиотек нет.

## Воспроизведение генерации

Проверенное окружение: Windows, Python 3.14.2, CPU, четыре потока PyTorch.
Версии численных библиотек зафиксированы в manifest; полный список пакетов —
`scripts/requirements-audio-lock.txt`. Sionna устанавливается только в отдельное
окружение генератора. Quarto build и GitHub Pages её не требуют.

Из корня проекта:

```powershell
python -m venv .tools/audio-env
.tools/audio-env/Scripts/python.exe -m pip install -r scripts/requirements-audio-lock.txt
.tools/audio-env/Scripts/python.exe scripts/benchmark_audio_channel.py
.tools/audio-env/Scripts/python.exe scripts/generate_audio_channel_demo.py
.tools/audio-env/Scripts/python.exe -m pytest -q
python scripts/check.py
```

В Linux используйте `.tools/audio-env/bin/python`. Для замены источника:
`scripts/generate_audio_channel_demo.py --source path/to/mono-pcm16.wav`.
Частота и длина читаются из WAV; исходник нормируется по пику. Для короткого loop
следует подготовить плавные границы исходного файла. Модель менять не нужно.

Сохранённые пакеты, manifest и результаты benchmark коммитятся. Python-модель,
интерфейс, документация и SVG/CSV остаются текстовыми; бинарные PCM — небольшие
производные assets, проверяемые по SHA-256.

CI запускает быстрые тесты с numpy/pytest и проверяет уже рассчитанные assets.
Три теста, которым нужен реальный LDPC, выполняются в полном offline-окружении
и пропускаются в лёгком CI. Дополнительно проверены независимая теоретическая
мощность ошибки PCM, точное сохранение всех отсчётов без битовых ошибок и побайтовое
совпадение сохранённого некодированного аудио с независимо рассчитанными решениями
по символам. Это исключает добавление отдельного шума после PCM-декодирования.
Локально проверяется вся цепочка, включая двукратную
генерацию и побайтовое совпадение результатов. Сборка выполняется через обязательный
`python scripts/check.py`, деплой — существующим workflow GitHub Pages.
