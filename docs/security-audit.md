Один workflow `.github/workflows/check.yml` выполнял тесты, Quarto 1.10.18, загрузку `course/_site/` и Pages deployment; PR проходили сборку без публикации. Проверок секретов и локальных hooks не было. Actions использовали изменяемые version tags. `render` уже имел `contents: read`, отдельный `deploy` — `pages: write` и `id-token: write`; `pull_request_target` отсутствовал.

Quarto строит только `course/`, ресурсы перечислены в `course/_quarto.yml`; корневые `design/`, `docs/` и инструменты в сайт не входят. `.gitignore` уже исключал сайт, кэши, `.venv/`, `.tools/` и `design/`, но не стандартные файлы credentials. Документация предупреждала о секретах Apps Script и закрытых ответах Google Forms: локальные экспорты credentials, ключей и ответов остаются потенциальными источниками утечки. Tracked-файлов с именами `.env`, `*.key`, `*.pem`, `*credentials*` при аудите не найдено. В проекте нет потребности в новой `.env.example`.

Read-only GitHub API подтвердил Pages `build_type: workflow`. В удалённом репозитории также один файловый workflow публикации; служебный Dependabot Updates не публикует сайт. Secret Scanning и Push Protection включены. Environment `github-pages` ограничен веткой `main`. Branch protection для `main` отсутствует (API 404 «Branch not protected»), rulesets отсутствуют. Настройки не изменялись.

## Итоговая цепочка

`source-scan (вся история + рабочие исходники) → render (тесты + сборка) → сканирование всего course/_site/ → upload → deploy`.

Любой неуспех до upload исключает загрузку потенциально скомпрометированного артефакта. Jobs используют стандартную зависимость GitHub Actions от успешных предшественников, без `always()` и `continue-on-error`. PR и другие ветки не публикуются; ручной запуск `main` также проходит все проверки. При успешной цепочке сохранены прежние каталог артефакта, environment и Pages deploy action.

## Результаты проверки

- Gitleaks 8.30.1 установлен из официального релиза, SHA-256 проверен. История всех refs (включая diff merge-коммитов) и текущее рабочее дерево: **находок нет**.
- `python scripts/check.py`: **успешно**, Quarto 1.10.18, все **20 страниц** собраны.
- Свежий Pages artifact: **106 файлов**, **находок нет**. Проверены HTML (20), JS (43), JSON (2), CSS (16), SVG (13), PCM (4), CSV (2), PNG (2), TXT, WEBP, WOFF и XML (по одному). Непубличных корневых каталогов `design/`, `docs/`, `scripts/`, `.github/` в результате нет.
- `python -m pytest -q`: **62 passed, 1 skipped**. Пропуск — существующий необязательный тест Sionna; тесты защиты не пропускались.
- **19 тестов защиты**: безопасные исходники/index/artifact; фиктивный токен в новых исходниках, staged при чистой рабочей копии, удалённой истории, другой ветке, merge-коммите, HTML/JS/JSON/CSS/TXT/ENV и ZIP; невозможность обхода через inline allow/local config; отсутствующий artifact и сбой сканера; порядок и зависимости workflow.
- Настоящий `pre-commit install` в отдельном временном репозитории: безопасный коммит проходит, коммит с фиктивным токеном блокируется, значение не выводится. Hook рабочего репозитория автоматически не устанавливался.
- Конфигурация pre-commit и YAML workflow валидны; **actionlint 1.7.12** не нашёл ошибок; `git diff --check` проходит.

Проверка блокировки deployment выполнена по конфигурации зависимостей workflow и интеграционным кодам завершения сканера. **Новый workflow ещё не запускался на GitHub, новый сайт не публиковался**: push/merge и живой deployment в задаче не выполнялись. Первый GitHub run должен подтвердить установку на Ubuntu и штатный deployment; локальная успешная сборка не выдаётся за подтверждение удалённой публикации.

## Что остаётся владельцу

Secret Scanning и Push Protection уже включены. Pages Actions и ограничение environment на `main` также настроены. Требуется включить branch protection/ruleset для `main`: PR, обязательные checks `source-scan` и `render`, контроль обходов и ревью изменений защиты; подробности в [руководстве](security.md). Изменение настроек требует отдельного согласования.

Текущая цепочка автоматически блокирует свою публикацию при ошибке, но **защита всего репозитория от обхода не гарантируется**, пока можно напрямую менять workflow в незащищённой ветке. Администратор может менять настройки и после включения правил. Hooks обходятся, Push Protection не покрывает все секреты, Gitleaks не распознаёт любые закрытые данные и бинарные форматы. Полные границы и порядок отзыва/ротации секретов описаны в [руководстве](security.md).
