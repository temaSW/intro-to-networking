# Пошаговые модели данных и сетевого узла

Два независимых компонента подключаются через `network-node-ui.js`:

- `data-network-node="build"`: одно содержимое для двух адресатов; сведения о назначении; заголовок и нагрузка пакета. Три шага.
- `data-network-node="forward"`: входной кадр; выделение пакета; решение; новый кадр; приём следующим узлом. Пять шагов для пересылки, три для местного приёма и отсутствия известного пути.

Чистая предметная модель — `course/interactives/network-node-model.js`; интерфейс — `network-node-ui.js`. Стили находятся в `course/styles/network-node.css`. Корневые контейнеры не используют общих изменяемых переменных. Компоненты имеют собственные параметры и этапы; выбор адресата не изменяет другой экземпляр. Изменение назначения сохраняет номер шага, если он доступен, иначе ограничивает его последним допустимым шагом.

## Условия и границы

Источник С передаёт строку «Привет». Назначения Д и Е известны узлу У: продолжение через В и Г соответственно. Назначение У означает местный приём; для Ж направления нет. Это явно заданная достижимость, не алгоритм маршрутизации и не таблица IP-префиксов.

Модель показывает функциональный фрагмент обычной сетевой пересылки, объясняемый далее на примере IP. Адреса символические; подписи «источник», «назначение», «получатель кадра» обозначают роли и не являются полным форматом стандарта. Полезная нагрузка не меняется. Другие изменяемые поля сетевого заголовка, проверка ошибок, изменение размеров блоков, адресное разрешение, преобразование адресов и туннелирование не моделируются. Рассматриваемый пакет помещается в кадр каждого участка. В реальном оборудовании функции могут быть распределены.

Первый шаг `build` предоставляет наблюдателю только содержимое: смена намерения отправителя не меняет эти наблюдаемые данные. Следующие шаги делают назначение доступным. Входной кадр предназначен У на своём участке; выходной — В или Г. Сетевое назначение и содержимое сохраняются в показанном пути. Шаг приёма следующим узлом не изображает доставку конечному серверу.

## Интерфейс и использование

Предметный параметр — адресат; управление показом — предыдущий и следующий шаг. Навигация останавливается на границах. Вопрос и рисунок сопровождаются закрытым пояснением каждого шага. Автовоспроизведения нет. Все элементы управления доступны с клавиатуры, имеют видимый фокус и используют общую светлую и тёмную палитру. На узком экране кадры сравнения располагаются вертикально.

Включения `network-node-build.qmd` и `network-node-forward.qmd` содержат текстовые резервные объяснения. При отключённом JavaScript остаются эти объяснения и статические схемы лекции, без неработающих кнопок. Самостоятельная страница — `course/reference/network-node.qmd`; лекция использует те же компоненты.

## Проверка

`python -m pytest -q tests/test_network_node.py`: наблюдаемая неопределённость без назначения, сохранение сетевого адресата и содержимого, смена канального получателя, местный приём, отсутствие направления, независимость экземпляров и границы шагов. Браузерная проверка охватывает каждый шаг и каждое назначение, две темы, ширины 1440/390/320, раскрытие пояснений, клавиатуру и резервный текст без JavaScript. Сборка — `python scripts/check.py`.
