# Общий выход: закреплённые доли и статистическое обслуживание

Компонент темы 05: `course/_includes/multiplexing-experiment.html`, чистая модель `course/interactives/multiplexing-model.js`, интерфейс `multiplexing-ui.js`, стили `course/styles/multiplexing.css`. Новых зависимостей нет. Для повторного использования подключить CSS и модуль, затем включить HTML; каждый корневой `data-multiplexing` независим, идентификаторы не нужны.

## Предметная постановка

Эксперимент длится 1000 мс. N источников имеют период 100 мс и активны первые p мс своей фазы; p — целый процент активности. Активный источник порождает один пакет 1000 бит каждую миллисекунду: 1 Мбит/с. Фазы либо одинаковы, либо равномерно распределены по периоду (это детерминированные разные фазы, **не независимые случайные источники**). Одновременные поступления упорядочены циклически со сменой первого источника, чтобы не закреплять за одним постоянный приоритет. Входной список одинаков для обоих способов обслуживания.

Общий выход обслуживает в порядке поступления со скоростью C Мбит/с. Передача неперерываемая и длится 1/C мс. B — число мест ожидания, без пакета в передатчике. При свободном выходе пакет поступает в передачу сразу даже при B=0; при занятом и полном буфере новый пакет отбрасывается. Завершение ровно в момент поступления обрабатывается первым.

В варианте закреплённых долей каждый поток имеет идеальный постоянный канал C/N и отдельный буфер; суммарно B мест. Целые места распределены поровну с остатком первым источникам. Сериализация длится N/C мс; доли не заимствуются. Утилизация усредняется по N долям, включая незанятые. Это сравнение политик разделения ресурса, **не точная симуляция временных позиций TDM и не модель установления/блокировки телефонных вызовов**. При входной скорости выше доли очередь находится перед каналом. Поэтому задержка включает разное время передачи в двух вариантах. При B<N часть источников не имеет памяти ожидания; это существенное следствие разделённой памяти, а не только разделённой полосы.

## Наблюдения и ограничения

- Выходная занятость — интеграл времени реальной передачи в окне, делённый на доступное время ресурса; учитывается часть незавершённого пакета.
- Передано — число полностью завершённых пакетов до 1000 мс включительно. Остаток включает ожидающие и находящиеся в передаче. Сохраняется `поступило = передано + потеряно + остаток`.
- Среднее ожидание и полная задержка (ожидание + сериализация) считаются только по завершённым пакетам. Не являются оценкой стационарного среднего; окно короткое. Потери и остаток всегда показаны рядом.
- График показывает суммарное число ожидающих пакетов каждые 10 мс на неизменной шкале 0–240. Это отсчёты, не точный максимум очереди; числовая таблица доступна через раскрытие.
- Нет распространения, обработки, ошибок, повторов, протокольных заголовков, управления перегрузкой, приоритетов, резервирования маршрута и сигнализации. Модель относится к одному выходу; выводы не следует переносить на всю сеть без учёта других узких мест.

Ритм опыта: гипотеза о разных/совпавших всплесках → один параметр → график и счётчики → объяснение через спрос и доступный ресурс. Изменение числа потоков также меняет закреплённую долю C/N. При непрерывной нагрузке и достаточной памяти преимущество статистического распределения уменьшается.

## Проверка

`python -m pytest tests/test_multiplexing.py` проверяет баланс пакетов, предел выхода, буфер, точный случай одного потока, влияние всплесков и памяти, независимость повторов и допустимость параметров. `python scripts/check.py` строит HTML. Браузерная проверка: обе темы, 1440/390/320 px, клавиатура, нулевые и предельные параметры, отсутствие JavaScript, таблицы и локальная прокрутка.
