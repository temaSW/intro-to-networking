# Карты структуры передачи: ИКМ и NR

Два независимых компонента: `[data-pcm-frame]` и `[data-nr-frame-map]`. Предметная модель — `course/interactives/transmission-frame-model.js`, интерфейс — соседний `transmission-frame-ui.js`, оформление — `course/styles/transmission-agreement.css`. Экспортируемые функции монтажа допускают несколько экземпляров с отдельным состоянием. Компоненты используются в лекции 06.

## ИКМ

Структура E1 / ИКМ-30: 32 КИ × 8 бит, 125 мкс, 2,048 Мбит/с. Выбран вариант с поканальной сигнализацией (CAS), без CRC-4. В КИ 0 чётных циклов биты 2–8 — 0011011, в нечётных бит 2 равен 1. Служебные значения заданы для демонстрации без аварии; бит Si выбран равным 1. В КИ 16 цикла 0 сверхцикла — признак 0000; циклы 1–15 несут сигнализацию пар каналов n и n+15. Слова речи и сигнализации выбраны для различимости, не моделируют аудиокодек.

Регуляторы: выбранный КИ, цикл сверхцикла 0–15, смещение начала приёмника 0–255 бит. Такт считается восстановленным. Сдвиг на один бит смешивает части слов; сдвиг на 8 бит сохраняет границы слов, но нарушает канальное соответствие. Чтение через конец цикла учитывает следующий цикл сверхцикла. Автоматический поиск синхронизма и аналоговое восстановление такта не моделируются. При смене выбранного КИ смещение сохраняется.

## NR

Нормальный CP, разнос 30 кГц: кадр 10 мс, десять подкадров по 1 мс, двадцать слотов по 0,5 мс, четырнадцать символов. CP — циклический префикс. FDD показывает две полосы с общей временной шкалой; TDD — одну полосу с примером D-D-D-S-U. Специальный слот S: 10 нисходящих символов, 2 защитных, 2 восходящих. Конфигурация выбрана для объяснения, не является универсальной конфигурацией сети.

Обзор содержит типы ресурсов разных участников. Этапы показывают отдельные функциональные фрагменты, не последовательные кадры одной процедуры. Временные позиции SIB1, PRACH, ответов, назначений и пользовательских данных иллюстративны. Не утверждается, что все процедуры укладываются в 10 мс. В обзорном поисковом SSB выбран допустимый кандидат для 30 кГц (начало в символе 4); периодическое повторение и лучи не моделируются. SSB присутствует только в примере кадра с его передачей.

SSB раскрывается по §7.4.3 TS 38.211: четыре относительных символа, 240 поднесущих; PSS — символ 0, k=56…182; SSS — символ 2, k=56…182; PBCH/DM-RS — символы 1 и 3, k=0…239, и символ 2, k=0…47 / 192…239. Для физического идентификатора 0 DM-RS занимает каждую четвёртую поднесущую этих областей (k mod 4 = 0); данные PBCH занимают оставшиеся позиции. Графические области PBCH рисуются фоном, поверх — замещающие их пилотные позиции, без физического наложения. Индивидуальные DM-RS PDSCH/PUSCH обозначаются на обзорной карте; их точная сетка не моделируется.

PRACH изображается отдельным окном: его длительность и нумерология зависят от конфигурации. Оно не подменяется четырнадцатью символами обычного слота. Сетка символов для управления/данных показывает функцию части ресурса, без точных выделений по частоте и без алгоритма планировщика. Не показанные ресурсы не обязательно свободны.

## Источники и проверка

- [ITU-T G.704](https://www.itu.int/rec/T-REC-G.704-199810-I/en), §2.3, §5: структура E1 и сигнализация.
- [3GPP TS 38.211](https://www.etsi.org/deliver/etsi_ts/138200_138299/138211/17.06.00_60/ts_138211v170600p.pdf), §4.2–4.3, §7.4.3: кадры, слоты, SSB.
- Назначение каналов и процедур связано с источниками в лекции.

Проверки: смысловые инварианты модели в `tests/test_transmission_frames.py`, `python scripts/check.py`, браузерная проверка выбора элементов и этапов, FDD/TDD, сдвигов ИКМ, клавиатуры, светлой/тёмной темы и узкого экрана. Больших зависимостей нет.
