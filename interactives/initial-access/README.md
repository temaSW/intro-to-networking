# Первоначальный доступ: модель по времени

Страница `course/reference/initial-access.qmd` — три последовательных независимых опыта: один терминал; конкуренция и повтор; непрерывная нагрузка. Лекция 06 сохранена в состоянии до работы над этим компонентом.

## Запуск

`quarto preview course`. Встраивание: CSS `styles/initial-access.css`, модуль `interactives/initial-access-ui.js`, контейнер `<div data-initial-access="single"></div>` (также `contention`, `load`). Пути относительно страницы. Нативные модули соответствуют существующим интерактивам проекта; нет новых зависимостей, marimo или Pyodide. `mountInitialAccess(root)` возвращает контроллер с текущей моделью, `reset()` и `stop()`.

## Основание переработки

Первый вариант был панелью переключаемых состояний. Эта версия построена вокруг часов модели, реальных событий в окнах, очередей и занятых ячеек. Источники просмотрены 7 октября 2026:

- [Ohio University, Slotted ALOHA Simulation](https://www.its.ohio.edu/slottedaloha/): попытки узлов на временной сетке и исходы слотов; использовано представление истории передач, без копирования кода и дизайна.
- [MIT 6.02 Lab 7](https://web.mit.edu/6.02/www/s2010/handouts/labs/lab7.shtml): моделирование по времени, очередь пакетов, повторы, использование ресурса. В нашем опыте студент управляет моделью, не пишет код.
- [ns-3, LTE model design, Random Access](https://www.nsnam.org/docs/release/3.25/models/html/lte-design.html#random-access): разделение попытки, ответа и служебного ресурса дальнейшего сообщения. Версия документации зафиксирована; её протокольное упрощение конфликтов используется как пример допустимой модели, а не точного PHY.
- [ETSI TS 138 321 V18.1.0, §5.1](https://etsi.org/deliver/etsi_ts/138300_138399/138321/18.01.00_60/ts_138321v180100p.pdf): окно ответа, выбор общего ресурса и случайный повтор. Здесь нет заявления о соответствии LTE/5G.

## Время и ресурс

`step()` продвигает время на одно окно. Кадр из семи окон: широковещание, общий доступ, ответ, индивидуализация, запрос, назначение, данные. Время условное, не миллисекунды. Ячейка доступа — независимая возможность в общем окне. Одинаковые выборы одновременно конфликтуют; одиночные принимаются без ошибок и захвата. Терминал узнаёт о неуспехе по отсутствию ответа до конца следующего окна, а не мгновенно от всезнающего контроллера.

Повтор назначается на кадр `текущий + 1 + U{0,…,backoff−1}`. При `backoff=0` задержка нулевая; при одной возможности синхронные терминалы могут конфликтовать бесконечно. Успешные терминалы больше не участвуют в конкуренции. Генератор воспроизводим по seed; reset сбрасывает также генератор. Другой случайный опыт увеличивает seed, не меняя параметры.

Сеть и терминал имеют отдельные сведения. После обнаружения попытки сеть создаёт временный контекст; терминал узнаёт его только из ответа. Ответ содержит назначение **служебной** ячейки следующего окна. После передачи индивидуальных сведений сеть различает терминал. Это функциональный обмен, без аутентификации и форматов PDU.

Известные терминалы имеют согласованные служебные мини-ячейки для адресных запросов. Сеть узнаёт размер очереди только из запроса. Планировщик работает с сообщённым размером, а не читает актуальную очередь напрямую. Заданный пользовательский ресурс выдаётся циклически по одной ячейке за проход до исчерпания потребностей или ёмкости; возможны несколько ячеек одному терминалу. Курсор движется после последнего реального назначения, что предотвращает голодание при одной ячейке. Назначение содержит точный tick следующего окна данных; `transmit()` запрещает его использовать раньше или позже. После передачи назначение расходуется.

## Опыты и интерфейс

Один терминал: сначала студент получает правила, затем отдельно создаёт блок и выполняет предметные действия до передачи. Кнопка проверки разрешения показывает, почему отправить данные ещё нельзя; эта проверка не занимает ресурс и не передвигает время. Последовательность передачи видна на схеме и сохраняется на сетке.

Конкуренция: у каждого терминала один блок. Настройки числа терминалов, возможностей и случайного ожидания независимы от других опытов. Шаг — одно окно; кадр целиком — до ближайшего конца кадра; запуск идёт по одному окну каждые 800 мс и останавливается после доставки всех блоков или при скрытии документа. Студент может остановить процесс в любой момент. Нулевое ожидание намеренно позволяет изучать постоянные конфликты.

Нагрузка: новые блоки появляются у каждого терминала независимо с заданной вероятностью за кадр, **даже если он уже занят**. Непереданные блоки остаются в FIFO-очереди; перегрузка не маскируется отбрасыванием приходов. Известные терминалы повторно запрашивают ресурс без нового первоначального доступа. `arrivals − delivered = backlog` сохраняется на каждом шаге. Настройки сбрасывают только свой опыт. 100 кадров — 700 вызовов модели, без пропуска событий.

Схема показывает выбранный терминал и до трёх соседей при большой сети; все терминалы доступны в выборе и в таблице состояния. Сетка сохраняет последние 14 окон и отмечает будущие назначения в точных ячейках; строки представляют независимые общие и пользовательские ресурсы. Адресные служебные мини-ячейки сгруппированы. Не утверждается, что реальные размеры всех сообщений одинаковы. Светлая и тёмная темы наследуют переменные курса. На телефоне прокручиваются только схемы/сетка; элементы управления доступны с клавиатуры. Движение стрелок выключается при `prefers-reduced-motion`.

## Метрики и пределы

Успех — обнаруженная одиночная попытка. Конфликт — один общий вариант с несколькими попытками. Средние попытки — только по успешным доступам; задержка первого назначения — от первого блока, только для получивших назначение. Использование данных — доставленные блоки / доступные пользовательские ячейки в завершённых окнах данных. График показывает накопленные приходы, доставку и текущую очередь. История сетки ограничена 200 окнами, журнала — 250 событиями, графика — последними 1000 кадрами; метрики и очереди не обрезаются.

Для первого одиночного блока шесть служебных действий: чтение общих правил, попытка, ответ, индивидуализация, запрос и назначение. Служебный ресурс считается достаточным; его размеры и доля общего физического ресурса не вычисляются. Нет распространения, модуляции, ошибок приёма, захвата, потерь ответа или точных процедур стандарта. Терминал считается синхронизированным до начала опыта.

## Проверка

`python -m pytest tests/test_initial_access.py`; `python scripts/check.py`. Тесты проверяют временные ограничения, служебное назначение, отдельное знание сети, конфликт и тайм-аут, случайный повтор, постоянный конфликт без ожидания, эксклюзивность и справедливость назначений, планирование по сообщённой очереди, накопление при перегрузке, баланс блоков и воспроизводимость reset.
